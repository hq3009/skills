# 评审意见概要写作范式

本文件规范 `评审意见.md` 中"评审意见概要"模块的写法。该模块位于"评审意见"之后、"三问三看三查三核"之前，是整份评审意见的"摘要页"，供业务处室和分管领导在半页到一页内快速判断：项目"卡"在哪、要改什么、钱要不要动、动多少。结构上由两部分组成：开头一段不编号的总体意见 + 3—6 条编号要点。

撰写顺序与文档顺序一致：**先完成"评审意见"正文，再浓缩出"评审意见概要"**，避免出现撰写在后、文档在前的错位。

## 一、概要与正文的分工

| 维度     | 评审意见概要                                | 评审意见正文                                 |
| -------- | ------------------------------------------- | -------------------------------------------- |
| 读者     | 处领导、分管领导，用于快速决策              | 申报单位、业务处室，用于逐条整改             |
| 篇幅     | 总体意见段（1—2 句，不编号）+ 3—6 条编号要点，每条 1—3 句                         | 按问题逐条展开，条目数不限                   |
| 结构     | 总体意见段（不编号）+ 各条"判断 + 关键数据 + 整改动作"                  | 意见 + 理由 + 建议，三段式                   |
| 编号     | 总体意见段不编号；要点 1. 2. 3.（本模块 3—6 条独立起编）           | 1. 2. 3.（按条连续编号，与概要编号互不混用） |
| 数据     | 只保留最有说服力的一两个数                  | 分项明细、历年序列、完整测算过程             |
| 交叉引用 | 不引用前面评审意见的编号，不写"详见第 X 条" | 可展开论证与推导                             |

两条硬性约束：

- **概要是正文的浓缩，不是正文的复述。** 正文已展开论证的，概要只留结论和数字。
- **概要点到的问题，正文必须有对应条目。** 不得出现"概要提了、正文没有"的悬空意见。

## 二、写作要求

**总体意见段。** 概要最前须先写一段不编号的总体意见（1—2 句）：先给总体判断（项目必要性及与部门职能的相关性），再概括主要问题方向并点明评审结论与调整方向；与正文总体意见口径一致但更简练，不写"具体意见如下："，不重复各条细节，不计入 3—6 条的条数。其后各条仍按下述要求撰写：

1. **判断先行。** 第一句直接给出结论——"不合适""不合理""未提供""超标""应核减"，不做铺垫、不写背景。
2. **数字说话。** 每个判断后面必须跟一个可核验的数字：单价、数量、中标价、上年预算、执行率、标准上限、覆盖率。没有数字支撑的判断不写进概要。
3. **落在动作上。** 每条都收束为可执行的整改动作：补充提供 XX 佐证、调减至 XX 万元、取消该项、修订 XX 办法、按 XX 标准执行。
4. **不写套话。** 禁止"建议进一步完善""加强绩效管理""提高资金使用效益"这类无信息量的表述。
5. **按严重程度排序。** 依次是：硬伤（触碰红线）→ 边界与依据 → 测算与标准（涉及核减金额）→ 绩效与执行。
6. **金额核减单列收尾。** 涉及核减的，末条写"综上，建议将预算由 XXXX.XX 万元调减至 XXXX.XX 万元"，并说明核定依据。

## 三、高频切入角度

按严重程度分四档，起草时自上而下逐档扫一遍，命中的写入概要，未命中的跳过。

### A. 硬伤类（通常指向"不予入库"）

| 角度                 | 触发情形                                             | 示例句式                                                                                                                           |
| -------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 核心业务外包         | 部门法定职责、核心业务整体外包给第三方               | 核心业务外包不合适。将 XX、XX 等核心业务交由第三方运维人员承担，本质是将部门工作职责外包，属于负面清单。                           |
| 政府履职事项购买服务 | 应由内部力量完成的行政履职事项，通过政府购买服务转嫁 | 负面清单：应当由政府直接履职的事项，不得作为政府购买服务内容。该业务属 XX 单位法定履职事项，不得通过政府购买服务转嫁核心履职责任。 |
| 事权与支出责任不匹配 | 事项由区县落地执行，经费却由市级保障                 | 项目涉及各城区、各乡镇，由市级保障不合理。日常 XX、XX 均由区县大队落地执行，相应经费应由所在区县保障。                             |
| 无政策依据           | 奖励、补贴、补助无上级或本级文件支撑                 | 无依据。从国家 XX 总局到省 XX 局，均未出台对本轮 XX 评定给予奖励的文件。                                                           |
| 重复申报/重复激励    | 同一实绩多次授奖，或多渠道资金叠加保障同一内容       | 激励对象高度重叠。本次评选所依据的核心业绩，大多就是其获评原有人才称号、领取过往奖励的同一批成果，属"同一实绩、多次授奖"。         |

### B. 边界与依据类（需补文件或调整口径）

| 角度             | 触发情形                                                | 示例句式                                                                                                                               |
| ---------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 项目边界混同     | 日常公用经费、长聘人员经费打包进专项项目                | 应区分项目边界。将整个校区的水电费、整体物业运维、通用设施维修等常态化运转的公用经费打包进专项培训项目不合适，应剔除日常行政运转开支。 |
| 项目属性走错     | 应走政务信息化/政府投资流程，却按业务类或专项公用类申报 | 项目属性：该项目应作为政务信息化项目申报，而非业务类项目；应先经数据局预审，再报送财政部门评审。                                       |
| 前置审批缺失     | 新采购、新建项目未经行业主管部门前置审核                | 对于新采购项目，应提供发改部门和数据局的前置审批意见。                                                                                 |
| 年度错配         | 跨年度事项排入错误预算年度                              | 2028 年召开 XX 会议的经费保障应排入 2028 年预算，而非安排在 2027 年。                                                                  |
| 政策到期或应修订 | 依据文件已过有效期或明显滞后                            | 上一轮文件为 2022 年制定，已到修订时间，建议趁文件修订取消该项补贴。                                                                   |

### C. 测算与标准类（涉及核减金额）

| 角度                 | 触发情形                                                    | 示例句式                                                                                                                         |
| -------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 单价与实绩背离       | 报告测算单价明显高于实际执行价或可沿用价                    | 处置费单价计算不合理。绩效报告按 196.11 元/吨测算，而实际综合单价已降至约 81.9 元/吨，且可沿用。                                 |
| 超财政支出标准       | 取费超过现行支出标准或制度规定的上限                        | 按财政支出标准，中级技术职称及以下专业人员每半天不超过 500 元，副高级不超过 800 元，该项目成本定额超标。                         |
| 历史对标异常         | 业务量未明显增加，预算却大幅增长；或与上年中标价/合同价背离 | 以维修维护费约 197.6 万元为例，相比 2026 年中标价 157.39 万元上涨 20% 以上，需说明详细理由；其余各类维修也需对比 2026 年中标价。 |
| 顶格测算             | 按满额、顶格数量或 100% 发放口径测算，未按实际发生数        | 事前绩效报告按顶格获奖数量、顶格奖励金额测算，不科学。应按以往年度实际获奖数量、实际奖励金额测算，相应核减预算需求。             |
| 数量基数不实         | 测算人数/户数/台数与实际规模、流失率或总量口径不符          | 退租房维修偏高。按入住率 95% 计算，退房约 100 套，而预算按 160 套、每套 5000 元测算，明显偏高。                                  |
| 未扣减收益           | 项目有租金、收费等收入未冲抵支出                            | 应扣减小区商铺的租赁收入，按收支两条线测算净需求。                                                                               |
| 缺多方案比选         | 未比较自主实施、部分外包、全部外包等方案的投入产出          | 大量经费拟采用服务外包模式，对现有人员编制、专业能力仅简单表述"力量有限"，缺少"自主实施、部分外包、全部外包"多方案投入产出比对。 |
| 周期性事项未按年分摊 | 非年度内一次性发生的任务按全额计入当年                      | 350 棵大型树木修剪及清运 12.6 万元，大型树木一般分年修剪，不应在同一年全额安排，应核减费用。                                     |

### D. 绩效与执行类（需完善后入库）

| 角度               | 触发情形                                                      | 示例句式                                                                                                                                   |
| ------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 必要性缺量化支撑   | 未梳理现状存量、瓶颈与供给缺口，无流量、受众规模等量化测算    | 缺少现状短板剖析与量化支撑：未梳理片区现状路网资产存量、通行瓶颈、供给缺口，无交通流量预测、服务受众规模等量化成果；成本效益分析流于形式。 |
| 延续项目缺运营复盘 | 到期延续/存量项目未运用运营监测数据论证现阶段继续拨付的必要性 | 到期延续类存量项目必要性论证未结合当前运营实际，仅复述建设期历史规划定位，未运用实际车流量、通行实效等运营监测数据。                       |
| 绩效指标缺失       | 关键产出、质量、时效指标空缺                                  | 完善指标，应增加：1. XX 发放覆盖率 100%；2. XX 按月发放到位率 100%；3. XX 按期足额申报缴纳完成率 100%。                                    |
| 指标逻辑错误       | 方向设反、只有上限无下限、区间过宽                            | "全年各项保障事项完成率≤100%"逻辑错误，应修改为按期完成率≥98%；"项目经费预算执行率≤100%"设置错误，应修改为=100%。                          |
| 指标与预算未挂钩   | 指标取值、评分基准、数据来源未明确，无法用于年度考核          | 绩效部分只说明考核框架与付费规则，未形成可直接用于年度预算考核的具象绩效指标，指标取值、评分基准、数据来源均未明确。                       |
| 执行率偏低         | 当期执行进度明显滞后                                          | 2026 年预算截至 7 月底执行率仅 37.71%，需提供执行进度慢的说明，并相应核减 2027 年需求。                                                    |
| 增量无佐证         | 规模、面积、人数未显著变化，费用却明显增加                    | 场所面积未有显著增加，物业费却增加 402.6 万元，需提供详细佐证。                                                                            |

## 四、完整示例

以下示例为写法示意，数据为占位值，实际撰写时以报告及附件中的真实数据替换。

### 示例一：信息化类（结论：不予入库）

项目方向与部门数据治理职能相关，但核心业务外包、项目属性走错、运维边界不清等问题未解决，不具备入库条件。

1. 核心业务外包不合适。将大数据分析、网络安全、分布式系统等核心业务交由第三方运维人员承担，本质是将部门工作职责外包，属于负面清单。
2. 项目属性应为政务信息化项目而非业务类项目，应先经数据局预审，再报送财政部门评审。
3. 缺少近一年系统可用率、故障次数与处置时长、工单量等运行情况数据，无法判断本项目与既有运维合同的边界，也无法核实按需增补的必要性。

### 示例二：业务类（结论：调整后再审）

项目属部门专项业务、与履职相关，方向可行，但处置单价与经费总额测算同实绩明显背离，应按实际执行水平压缩预算后调整再审。

1. 处置单价测算与实际背离。报告按 196.11 元/吨测算，实际综合单价已降至约 81.9 元/吨且可沿用，应据实调整。
2. 经费总额与过往年度相比明显偏高。2025 年日均处理 405.57 吨、全年预算 2794 万元，本年度日均处理 400 吨、预算 4138 万元，处理量未增加的情况下增幅过大。
3. 综上，建议按过往年度预算水平执行，调减预算至 2794 万元。

### 示例三：政策类（结论：调整后再审）

政策延续有上轮文件基础，但测算口径顶格、缺乏退出安排，应按实际兑付水平重新测算后调整再审。

1. 资金测算口径不科学。按制度规定奖励上限为每家 100 万元，报告按顶格获奖数量、顶格奖励金额测算，应按以往年度实际获奖数量和实际奖励金额测算。
2. 未设置政策到期后的退出安排，建议明确兑现期限与退出条件。
3. 综上，建议按近三年实际兑付水平核定本年度预算，相应核减需求。

### 示例四：建设类（结论：调整后再审）

项目属补短板的公共基础设施、立项方向可行，但必要性量化支撑不足、预拨清算机制存在风险，应完善后调整再审。

1. 缺少现状短板剖析与量化支撑。未梳理片区现状路网资产存量、通行瓶颈与供给缺口，无交通流量预测、服务受众规模等量化测算成果；成本效益分析直接取用"内部收益率＞8%"，未说明测算参数与基础数据来源。
2. 预拨比例偏高导致清算大额扣回，建议结合历史清算偏差率适当下调预拨比例，余款按年度考核清算后拨付。

## 五、自检清单

生成后逐项核对：

- [ ] 开头有一段不编号、1—2 句的总体意见段，置于最前，与正文总体意见口径一致，未写"具体意见如下："。
- [ ] 编号要点条数控制在 3—6 条（总体意见段不计入），每条不超过 3 句。
- [ ] 每条第一句都是明确判断，不是背景铺垫。
- [ ] 每条至少含一个可核验的数字（金额、数量、单价、比例、年份）。
- [ ] 每条都有明确整改动作，无"进一步加强""不断完善"类套话。
- [ ] 按硬伤 → 边界与依据 → 测算与标准 → 绩效与执行的顺序排列。
- [ ] 涉及核减的，已写明调整前金额、调整后金额及核定依据。
- [ ] 编号用阿拉伯数字加英文句点（1. 2. 3. …）；概要开头的总体意见段不编号，概要要点与正文条目、四组子项的编号各自独立、互不混用、互不引用。
- [ ] 未引用前面评审意见的编号，未出现"详见第 X 条"。
- [ ] 概要点到的每个问题，在"评审意见"正文中都有对应条目。
- [ ] 与"项目基本信息"中的评审结论、核定入库金额一致。

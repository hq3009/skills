# 宁波市财政预算项目事前绩效评估报告评审意见

## 背景

本技能用于生成宁波市预算项目事前绩效评估的专家评审意见，覆盖信息化类、政策类、业务类、建设类等各类财政支出项目。本 skill 产出两个 `.md` 文件，一个为"内容摘要"，一个为"评审意见"。

## 使用场景

用户要求生成"评审意见""三问三看三查三核""事前绩效评估专家评审意见"等内容的 Markdown 版本。适用项目类型包括：

- **信息化类**：信息系统建设、云资源租用、运维服务、设备购置，政务云扩容、系统适配改造、平台建设、数据迁移与运维保障等；
- **政策类**：补贴/补助政策、扶持/奖励政策等；
- **业务类**：公共服务、业务运行、购买服务、专项活动，贴息补贴、设备更新、专项建设、行业保障类等（投入规模大、实施周期长、绩效兑现受执行影响明显）；
- **建设类**：工程建设、维修改造、基础设施建设、政府投资项目（公共基础设施、公共服务能力提升、重点建设工程及配套保障）等。

## 核心步骤

1. 阅读运行时工作目录及子目录中的部门上报事前绩效评估报告、预算申报表、绩效目标表和各类佐证资料，提取项目核心内容，并将客观事实写入`内容摘要.md`。模板、写作范式和本技能说明仅作为规则参考，不作为项目事实来源。
2. **先做材料清单和事实核验**：区分报告正文、预算测算表、绩效目标申报表、历史执行资料、政策依据和其他附件；记录材料之间的金额、年度、项目名称、实施期限、项目属性及指标冲突。材料未提供或相互矛盾的信息，标注"未提供"或"待核实"，不得自行补造。
3. **识别项目类型**：按主要支出对象判断项目属于信息化类、政策类、业务类或建设类。对象兑付以政策类为主，购买或开展服务以业务类为主，形成固定资产或工程成果以建设类为主，系统、云资源及软件服务以信息化类为主。混合项目按预算分项分别选用范式，并注明主类型和子类型，避免整份报告套用单一类型检查项。
4. **提取项目基本信息**：从上报材料中提取项目名称、项目编码、预算部门、实施单位、资金总需求（实施期X年，年度XXX.XX万元）、事前评估周期、原申报结论和核定入库金额。材料未提供的字段填写"未提供"或"待核实"；不得根据项目名称、总额或常规做法推测日期、金额、历史数据、绩效结果或评审结论。
5. **校验预算和绩效数据**：以分年度预算和分项测算表为主要核验依据，检查分项金额合计、年度金额合计、实施期限、历史执行率、绩效指标和资金来源是否相互一致。只有材料明确均衡分配时，才可用总额除以实施年数进行辅助校验；发现差异须在摘要和评审意见中说明差异来源或列为待核实事项。
6. **撰写评审意见**：按"意见 + 理由 + 建议"三段式整理编号意见条目，结合 `references/写作范式.md` 中 ①—⑨ 常用条目与"四、共性问题与评审总纲"（一体化评审思路、三级测算审查法、共性短板清单）按需取用、改写、重排。每条意见须以报告或附件中的具体事实为依据，不能只套用通用表述；涉及金额时说明调整方向及依据。
7. **三问三看三查三核评估**：按模板逐项填写——三问（边界/事权/职能）、三看（立项依据/预期效益/经济节约）、三查（重叠交叉/实施风险/筹资合规）、三核（目标匹配/指标细化/指标预算匹配），行文言简意赅。四组内容必须独立回答，不引用前面的评审意见编号；判断和结论应直接依据上报报告及附件中的已核实事实，且不得与其矛盾。
8. **调用模板文件**：以 `assets/模板.md` 为结构基准，在`评审意见.md` 中生成三个部分："项目基本信息"、"评审意见"、"三问三看三查三核"，同时参考 `references/写作范式.md` 及对应类型范式。`内容摘要.md` 只记录材料事实、数据和待核实事项，不提前写入专家结论。
9. **校验编号和输出完整性**：检查评审意见编号是否连续；三问、三看、三查、三核分别在本组内使用①②③编号，四组之间不连续编号，也不得与前面的评审意见编号混用。模板中的12个子项须全部填写，每个子项原则上简短的一段文字；四组内容不得出现对前面评审意见的编号引用。同时检查是否残留占位符、金额单位是否统一、分项和年度合计是否一致。
   - "三问"：立项边界三问，结论通常"边界清晰/事权清晰/职能相关"，可点出必要性论证不足。
   - "三看"：独立判断立项依据、预期效益和预算经济性，直接依据报告及附件中的政策依据、历史数据和测算资料，不引用前面评审意见编号。
   - "三查"：重叠交叉（防重复购置/重复建设/重复补助）、实施风险（采购或实施滞后→执行率偏低）、筹资合规（中央资金分担须明示避免重复申报）。
   - "三核"：跨年度须有分年度目标；指标须量化；指标值须与预算/任务对应。

## 注意事项

### 关于内容注意事项

- **一体化评审思路**：四类项目统一按"必要性、可行性、绩效性、可持续性"一体化评审，意见撰写保持"评估结论—预算安排—执行监测"链条衔接；预算测算对高风险科目（设备购置、系统建设、运维费用等）按"参数依据→市场比价→同类对标"三级递进核验（详见 `references/写作范式.md` "四、评审总纲与共性问题"）。
- **共性短板逐项对照**：必要性偏宏观（缺不实施后果与替代方案比较）、绩效重任务轻成效（结果导向与资金效益关联不紧）、测算缺市场对标与同类对标、评估—预算—执行监测链条衔接不畅、实施里程碑与责任主体不细、文本规范问题（术语不统一/条款重复/要素缺项），评审时逐项对照、按需写入意见。
- **"必要性"要写"差距"而非"意义"**：报告"必要性分析"对项目作用泛化描述，未回答"为什么现在必须做、不做的后果"；应围绕差距展开——现有设施/能力/服务老化、短缺或已达容量瓶颈；安全、合规、民生保障等要求与现状存在差距；既有供给方式难以满足新要求等（对应范式第①条）。
- **到期延续/分期项目须补前期运行情况**：如果缺乏前期运行情况，则无法进行绩效评估，须按项目类型补充对应信息（见下表）。
- **资金测算须有明细 + 历史数据**：仅载明总额或合同金额，未提供分项测算（数量×单价）及测算依据；应补分项明细并列示历年合同金额、实际支出、预算执行率（对应范式第③条）。不同类型项目的分项维度见下表。
- **绩效指标量化 + 约束力校准**：定性"有效提升"无法核验；指标值"≤5个"只有上限无下限、偏宽松；应结合近三年实际支出核定成本目标，数量改区间值，增结果性/约束性指标。
- **项目期限**：项目期限（如 2027—2029 三年）常只在报告末尾"绩效目标申报表"中，正文不写，需到表里找；资金总需求常标"实施期三年，年度XXX万元"，应以分年度预算表核对，不能默认年度额等于总额除以实施年数。
- **评审结论三选一**：予以入库 / 调整后再审 / 不予入库；金额缺失统一写"待调整完善后核定"或"待定"。
- **事实与判断分离**：`内容摘要.md`记录上报材料中的事实及材料缺口；`评审意见.md`记录专家分析、整改建议和评审结论。除非材料已有明确结论，不能把推测性判断写成申报单位原结论。
- **原结论与专家建议区分**：材料中的申报单位意见、评估机构意见或既有审核意见，应标明来源；本技能形成的结论应明确为专家评审建议，避免混淆。

### 格式注意事项

- **评审意见**：编号用 ① ② ③等；每条意见、理由、建议的组合一段。
- **三问三看三查三核**：三问三看三查三核子项按顺序排列，分为"三问"、"三看"、"三查"、"三核"4组；每组三条意见，分别使用本组内编号①②③，四组编号不连续、不互相引用，也不与前面的评审意见编号混用。每条意见用简短的文字。
- **收尾呼应**：总体意见末句点明"具体意见如下："。
- **文字风格**：使用中文全角标点，使用中文引号。
- **金额**: 金额统一单位为"万元"。
